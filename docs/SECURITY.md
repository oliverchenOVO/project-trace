# Security and local repository boundaries

Normal investigations are read-only. Git operations are fixed internal calls to rev-parse, status, log, show, diff and blame. The service also permits ls-files for future targeted path discovery. Inspection commands accept no arbitrary executable names, shell strings or Git argument arrays. Verification is a separate opt-in structured command/approval boundary. No repository script, package hook or content instruction can trigger execution.

The installed Git executable is resolved from absolute PATH entries and pinned to a canonical executable path. Relative/current-directory PATH entries and executables inside the selected repository are rejected. A repository-local `git.exe` cannot replace the installed CLI through Windows executable search order.

Git is spawned with executable + argument arrays, no shell, no optional locks, prompts disabled and hidden child windows on Windows. Inherited GIT_* variables are stripped. fsmonitor is disabled, signature verification is disabled, pager is fixed, and patches disable external diff and textconv; blame also disables textconv. Configured clean/smudge/process filters are disabled even during status/blame inspection. Recorded command arrays include the safety flags. Output is limited to 2 MB per stream and each Git operation has a 20-second deadline. Oversized or timed-out operations fail explicitly.

Repository roots are canonicalized and registered as session tokens. Sources are canonicalized, checked against the root, and must be regular files. Both slash styles of `..` traversal are rejected; file URLs are decoded before validation. Symlinks resolving outside the root are rejected. Source reads are capped at 512 KB and require UTF-8 nonbinary content. SHA-256 checks after analysis detect source changes; HEAD and worktree status are checked before and after collection.

Sensitive/generated path components are blocked: .git, .env, .env.*, *.pem, *.key, id_rsa, id_ed25519, credentials*, secrets*, node_modules, dist, build and coverage. These exclusions apply before source inspection and AI packaging. Relevant patch content is always restricted to the resolved file.

AI receives only explicitly previewed evidence excerpts, bounded per item and by a 32 KB working budget. Common credential assignments, bearer tokens, common provider token formats and PEM private-key blocks are redacted. Pattern redaction is not a complete secret scanner: review the context before sending it even to a local model. AI is fixed to loopback Ollama, with proxies disabled, no tools, structured output and strict evidence-ID validation. Hypothesis nodes cannot enter subsequent deterministic AI context.

The local SQLite database intentionally preserves original inputs and source excerpts. It is not encrypted. It stays outside the investigated repository and is never committed to GitHub. Access follows the current Windows user's filesystem permissions. Do not publish a case containing confidential material.

Test execution and bisect now require explicitly configured commands, a single-use approval token and owned isolated worktrees. The active repository cannot be selected as the execution location. The fixture creation script is a developer tool that creates real commits in its own new folder and refuses to overwrite an existing directory. It is not invoked by normal analysis.


Phase 1.1 execution inherits normal account permissions and network access. There is no OS filesystem sandbox; approved repository tests can affect external files. The UI discloses this before approval. Arbitrary shells/batch launchers are rejected; supported package-manager .cmd files are resolved to their installed Node CLI. No install operation is inferred or automatic. Hooks, checkout filters and submodule recursion are disabled for native Git administration. Windows suspended creation + Job Object assignment manages descendants on cancel/timeout/exit/crash. Output capture is bounded and stored outside source repositories.

Cleanup validates canonical containment, UUID ownership, repository marker and Git common directory before Git removal. Explicit retry can unlock an owned worktree or remove a validated unregistered partial creation, while preserving artifacts. Source before/after hashes cover nonignored checkout files and index state, not ignored files or arbitrary external effects. See [verification engine](VERIFICATION_ENGINE.md).
